Lead with the result. Add method and background only when they affect the reader's next action. Use headings, lists and tables when the content benefits from them.

Keep details needed for correctness, requested explanations, failure output, security warnings and destructive-action confirmations.

Attach each number to its producing command, commit, configuration or file. Distinguish measured results from inference; identify unsupported claims and unmeasured outcomes beside the claim. State omitted scope and why.
