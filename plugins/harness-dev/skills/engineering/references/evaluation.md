# Evaluate an instruction or workflow

Separate routing, task success and cost. A skill that loads correctly can still execute poorly; a silent skill in a broken environment has established neither a positive nor a negative result.

Define the behavior change and comparison before running. Use the repository's existing evaluator where one fits. Keep the rubric and expected result away from the acting candidate. Give it an ordinary user request, realistic prerequisites and a project-shaped workspace. Do not label candidate-visible paths with the treatment, intended answer or model identity. Comparing variants requires the same task and conditions; a judge sees neutral output labels on one scale.

Check the instrument on a known broken input and a valid positive control. A grader must fail when the promised behavior breaks and pass when the internal implementation changes without affecting the contract. Expected output must come from the requirement or independent reference, not the implementation under examination. Do not weaken a grader to make the candidate pass.

For routing, measure the real skill that is present in the candidate environment. Plugin and project names differ; do not infer one through a temporary stand-in. Use positive cases and neighboring negative cases with the premises actually present. Observe where the work went, not only whether the target stayed silent. Repeat trials when reliability matters and report both per-trial success and consistency across repeats.

Record the model and effort actually used, installed revision, environment, raw outputs, errors, timeouts and missing artifacts. An unavailable API or aborted session is not a model failure or a silent negative. Keep incomplete attempts visible in the accounting; explain exclusions instead of quietly shrinking the denominator. Check tool receipts and produced files rather than the candidate's account of what it did.

Promote only the conclusion supported by the experiment. Synthetic tasks, one model, a manual exercise or a small sample establish bounded evidence. If there is no comparison, do not claim improved model quality. End with the result, uncertainty, artifacts and the next observation that would change the decision.
