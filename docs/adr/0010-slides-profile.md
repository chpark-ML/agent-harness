# ADR-0010: 발표자료 프로파일은 렌더링을 하지 않고, 수치 추적만 기계로 강제한다

- **Status**: Accepted
- **Date**: 2026-08-06

## Context

개발·연구 결과는 결국 발표된다. 그 자리는 **추적 불가능한 수치가 인용되는 순간** 이다 — 노트에는 "이 표가 어느 run 에서 나왔는지" 가 적혀 있어도 슬라이드로 옮겨지면 숫자만 남고 근거는 떨어져 나가며, 그 숫자를 청중이 인용해 의사결정에 쓴다. `harness-research` 가 `ARTIFACTS.md` 로 세우는 불변량("run 으로 추적되지 않는 수치는 아직 결과가 아니다")이 가장 잘 깨지는 지점이 정확히 여기다.

동시에 **슬라이드 렌더링은 이미 잘 풀린 문제다.** `slides-grab` (npm) 이 plan → html → design → export 를 스킬 네 개로 덮는다. 우리가 HTML 레이아웃·테마·PDF 변환을 다시 만들 이유가 없고, 만들면 유지보수만 늘고 품질은 진다.

기존 규율과의 충돌도 하나 있다. [ADR-0009](0009-external-dependencies.md) 는 트리거가 겹치는 스킬 둘을 함께 배포하지 않는다는 규칙을 세웠다. "발표자료 만들어줘" 는 `slides-grab` 의 스킬들과 명백히 겹치는 트리거다.

## Decision

**`harness-slides` 프로파일을 만들되, 그 범위를 "산출물 → 서사" 로 한정한다.** 렌더링·디자인·내보내기는 하지 않는다.

1. **`results-deck` 스킬** — 저장소의 산출물(`FINDINGS.md` · `experiment_plan.md` · `ARTIFACTS.md`, 또는 변경 이력·릴리스 노트·벤치마크 출력)을 6장 골격의 개요로 바꾸고 `slides-grab` 에 넘긴다. 골격에서 **"얼마나 믿을 수 있나" 와 "무엇이 아직 아닌가" 를 필수로 둔다** — `FINDINGS.md` 가 번복을 보존하는 것과 같은 이유로, 뒤집힌 결과가 없는 발표는 뒤집힌 것을 지운 발표로 읽힌다.
2. **트리거 충돌은 negative routing 으로 푼다.** description 이 렌더링·디자인·편집·PDF 를 명시적으로 `slides-grab` 쪽으로, 노트 작성 자체를 `research-notes` 쪽으로 돌린다. ADR-0009 에서는 남의 스킬에 negative routing 을 넣을 수 없어 하나를 골라야 했지만, 여기서는 **역할이 실제로 겹치지 않으므로** (우리는 입력을 만들고 저쪽은 렌더링한다) 우리 쪽 description 만으로 갈린다.
3. **`check-claims.sh` — 추적을 스킬 지시가 아니라 스크립트로 강제한다.** 덱의 모든 숫자 토큰이 근거 파일에 있는지 기계로 대조하고, 없으면 exit 1. 주장이 아닌 숫자(연도·ISO 날짜·버전·목록 번호·슬라이드 참조)는 무시하고, 예외는 그 줄의 `<!-- no-claim -->` 로 명시한다.
4. **`slides-grab` 은 dependency 로 선언하지 않는다.** 플러그인이 아니라 npm 패키지이므로 `dependencies` 가 가리킬 수 없다. LSP 바이너리와 같은 취급 — `harnessctl doctor` 가 PATH 를 점검하고 설치 명령을 알려준다.

### 왜 스크립트인가 — 측정 가능성의 문제이기도 하다

"수치를 추적 가능하게 쓰라" 를 스킬 본문에만 적으면 그것은 guide 다. guide 가 실제로 지켜지는지는 에이전트 세션 A/B 로만 확인되고, [agent-layer §4b](../agent-layer.md#4b-무엇을-기대할-수-있나--측정된-것과-아닌-것) 가 재본 바로는 그런 A/B 는 팔당 수십~수백 세션이 있어야 20% 미만의 효과를 본다. **같은 규칙을 스크립트로 내리면 21 케이스로 확정된다.** 가드로 내릴 수 있는 것을 가이드로 두지 않는다는 원칙은 안전 원칙일 뿐 아니라 측정 가능성의 원칙이다.

`check-claims.sh` 는 훅이 아니라 **명령** 이다. 도구 호출을 막지 않는다 — 발표 초안은 도구 호출이 아니라 문서이고, 막을 지점이 없다. 대신 스킬 Step 3 이 이것을 돌리고, 통과 못 한 초안은 렌더링으로 넘기지 않는다.

### 검사가 일부러 못 하는 것

숫자가 **올바르게 쓰였는지** 는 보지 않는다. 근거 파일에 있는 숫자를 엉뚱한 문장에 붙여도 통과한다. 의미 검사는 정규식이 할 수 있는 일이 아니고, 그 방향으로 밀면 오탐이 늘어 하루 만에 우회된다. 실제로 벌어지는 사고 — **슬라이드에만 존재하고 어디에도 없는 수치** — 를 잡는 데 범위를 고정한다.

## Consequences

- 발표자료 요청이 렌더링 도구로 곧장 가지 않고 근거 수집을 먼저 지난다. 덱을 쓰기 전에 수치를 모으므로, 서사에 맞는 숫자를 찾는 순서가 뒤집힌다.
- `ARTIFACTS.md` 가 없는 프로젝트에서는 `check-claims.sh` 가 exit 2 (운영 실패) 로 끝난다. 이는 의도한 것이다 — 근거 파일 없이 통과시키면 검사가 있는 척만 하게 된다. 스킬 Step 1 이 그 표를 먼저 만들게 한다.
- 오탐 위험은 남는다. 주장이 아닌 숫자의 목록은 관찰로 만든 것이라 빠진 모양이 있을 수 있고, 검증기 21 케이스 중 7개가 "통과해야 하는 것" 인 이유가 그것이다. 새 오탐 모양이 나오면 케이스를 먼저 추가한다.
- `slides-grab` 이 없으면 이 프로파일은 개요까지만 만들고 끝난다. 그것만으로도 값을 하지만, doctor 가 안내하지 않으면 사용자는 끊긴 것으로 느낀다.

## Alternatives considered

- **직접 렌더링한다.** 거부. `slides-grab` 이 더 잘 하고, 겹치는 트리거 두 벌을 우리 손으로 만드는 꼴이다.
- **`harness-research` 에 넣는다.** 거부. 발표는 연구 전용이 아니다 — 릴리스 리뷰·데모·스프린트 보고에도 같은 사고가 난다. 별도 프로파일이면 `harness-dev` 사용자도 조합할 수 있다.
- **추적 검사를 훅으로 만든다.** 거부. 훅은 도구 호출을 가로채는데, 덱을 쓰는 행위에 대응하는 도구 호출이 없다. 파일명 패턴으로 Write 를 가로채는 방식도 생각했지만, 덱 파일명은 프로젝트마다 다르고 초안 저장을 막는 것은 잘못된 지점에서의 차단이다.
- **`ARTIFACTS.md` 없이도 통과시킨다.** 거부. 근거 파일을 선택 사항으로 두면 검사가 대부분의 프로젝트에서 무조건 통과하고, 그때부터 통과는 정보가 아니다.
