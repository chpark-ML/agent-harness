# 네 가지 축 — loop · harness · graph · orchestration

이 저장소가 다루는 문제는 하나가 아니라 넷이고, 넷이 서로 다른 자리에 설정된다. 축을 섞으면 "에이전트를 잘 굴리자" 같은 말이 되고, 그러면 무엇을 재야 하는지도 흐려진다.

**본 문서는 설계 노트다. 컨슈머에게 배포되지 않으므로 상시 컨텍스트 비용은 0 이다.** 범위·인벤토리·backlog 의 SOT 는 [`agent-layer.md`](agent-layer.md) 이고, 여기는 *어떤 레버가 어디 있고 남들은 어떻게 쓰는가* 만 다룬다.

축마다 다섯 칸을 채운다 — **정의 · 설정 지점 · 기존 방법 · 우리 현황 · 측정**. 다섯째 칸이 대체로 비어 있고, 그게 정직한 현재 상태다.

---

## 한 장 요약

| 축 | 무엇을 정하나 | 우리 위치 | 쟀나 |
|---|---|---|---|
| **harness** | 무엇을 막고 무엇을 규약으로 고정하나 | **본체** — 가드 6 · 규약 · 설치기 | ✅ 가드 27/29 · 브랜치 규약 10/12 |
| **loop** | 언제 멈추고 언제 다시 도나 | 규칙 없음 (R6 초안은 0 이 나와 철회) | ⚠️ 한 주장만 쟀고 **0** |
| **orchestration** | 어떤 일을 어느 모델·에이전트로 내리나 | **컨슈머용 에이전트 0** | ❌ 안 쟀다 |
| **graph** | 코드베이스를 어떻게 이해하나 | 자산 없음. LSP 만 (다른 층) | ❌ 안 쟀다 (LSP 는 결론 없음) |

---

## 1. Harness engineering

### 정의

에이전트가 **할 수 없게** 만드는 것과, **하기로 약속된 것**을 고정하는 것. 사고 방지와 규약. 이 저장소의 본체이며 [ADR-0001](adr/0001-harness-scope.md)이 범위를 여기로 못박았다.

### 설정 지점

| 어디 | 무엇을 | 성격 |
|---|---|---|
| `hooks/*.sh` + `hooks.json` | PreToolUse 차단 · Stop 정보 | **가드** — 통과 못 하면 도구 호출이 성립하지 않음 |
| `settings.json` `permissions` | allow / ask / deny 3티어 | **가드** |
| `CLAUDE.md` | 행동 5원칙 (전역 기본) | 가이드 |
| `.claude/rules/**` | path-scoped 규약 | 가이드, **프로젝트 스코프에만 설치** |
| `harnessctl` | 위 셋을 되돌릴 수 있게 설치 | — |

가드와 가이드는 대체 불가다 ([agent-layer §5](agent-layer.md)) — 가이드는 무시될 수 있고, 가드는 모든 케이스를 사전 인코딩할 수 없다.

### 기존 방법

- **Superpowers** — 작업 방법론을 스킬로. 가드는 없다.
- **`karpathy-guidelines`** — 원칙을 글로. 우리 §1–4 가 이것이다.
- **`caveman`** — 출력 토큰 절감. 우리 훅 계약과 충돌해 기각.
- **`claude-mem`** — 라이프사이클 훅으로 세션 캡처. 보류.

### 우리 현황

가드 훅 6 (차단 4 · 정보 2) · 권한 3티어 (allow 42 / ask 3 / deny 8) · 규칙 3 · 설치기 1.

### 측정

| 무엇 | 결과 |
|---|---|
| 가드가 사고를 막나 | **27 / 29**, 정상 작업 오탐 **2 / 24** |
| 글이 행동을 바꾸나 (브랜치 이름) | 0/12 → **10/12**, *p* ≈ 0.00007 |
| commit 제목 70자 | 6/6 대 6/6 — **0. 규칙에서 지웠다** |
| 제거하면 원래대로인가 | 92 assertion, 정준 동일 |

**이 축만 제대로 재봤다.** 그리고 재본 것 중 하나는 0 이었고 지웠다.

## 2. Loop engineering

### 정의

**언제 멈추고 언제 다시 도는가.** 세 척도가 있고 셋이 다른 자리에 설정된다.

| 척도 | 질문 |
|---|---|
| **턴** | 검증을 돌렸나. 같은 실패가 반복되면 무엇을 바꾸나 |
| **세션** | 오래 걸리는 일을 어떻게 띄우고 무엇을 기다리나 |
| **실험** | 조정과 재측정을 어떤 규율로 반복하나 |

### 설정 지점

| 어디 | 무엇을 | 척도 |
|---|---|---|
| agent frontmatter `maxTurns` | 서브에이전트의 턴 상한 — **기계적 상한** | 턴 |
| rules / `CLAUDE.md` §4 | 성공 기준·멈춤 조건 (가이드) | 턴 |
| 백그라운드 실행 + 완료 알림 | 폴링 대신 통지 | 세션 |
| `/loop` 스킬 · 스케줄러 | 주기 실행, 자기 페이싱 | 세션 |
| 벤치 스크립트의 짝비교 규율 | baseline → 조정 → 재측정 | 실험 |

**`maxTurns` 가 이 축의 유일한 하드 레버다.** 나머지는 전부 가이드이고, 가이드는 재봐야 값을 안다.

### 기존 방법

| 무엇 | 어디 | 크기 |
|---|---|---|
| `test-driven-development` | Superpowers | 320줄 — 실패하는 테스트를 먼저 |
| `systematic-debugging` | Superpowers | 283줄 — 고치기 전에 원인 |
| `verification-before-completion` | Superpowers | 120줄 — 완료 선언 전에 증거 |
| `executing-plans` | Superpowers | 64줄 — 체크포인트마다 검토 |

**Superpowers 가 이 축을 이미 두껍게 덮는다** (합 787줄). 우리가 얹을 자리는 그 위가 아니라 *멈춤 조건* 과 *세션·실험 척도* 쪽이다.

### 우리 현황

**없다.** `CLAUDE.md` §4 가 *"Define success criteria. Loop until verified"* 를 말하지만 멈춤 조건이 없다.

R6 초안(턴·세션·실험 세 척도, 525 tok)을 썼다가 **철회했다** — 아래 측정 때문이다.

### 측정

| 무엇 | raw | harness | 판정 |
|---|---|---|---|
| 검증 명령을 스스로 돌렸나 | **3 / 3** | **3 / 3** | **변별력 없음** |

첫 시도가 반드시 실패하는 과제를 주고 검증 명령을 언급하지 않았는데도 양팔 다 돌렸다. **검증을 돌리는 행동은 규칙이 사는 것이 아니라 모델이 원래 하는 것이다.**

**안 쟀다**: 멈춤 조건(같은 실패 2회 → 가정 재검토) · 세션 척도 · 실험 척도. 이 셋을 재는 과제 설계가 서기 전에는 규칙으로 올리지 않는다.

## 3. Orchestration

### 정의

**어떤 일을 어느 모델·effort·에이전트로 내리는가.** 메인 루프를 비싸게 두고 기계적인 일만 싼 티어로 내리는 것, 그리고 여러 에이전트에 일을 배치하는 것.

### 설정 지점

플러그인 에이전트 frontmatter 가 지원하는 것 (공식 문서 확인):

| 필드 | 값 | 쓰임 |
|---|---|---|
| `model` | `haiku` · `sonnet` · `opus` · `fable` · 전체 ID · `inherit` (기본) | 티어 |
| `effort` | `low` · `medium` · `high` · `xhigh` · `max` | 세션 effort 를 덮어씀 |
| `maxTurns` | 정수 | 루프 상한 |
| `tools` · `disallowedTools` | 도구 제한 | 권한 축소 |
| `skills` | 미리 로드할 스킬 | 컨텍스트 |
| `memory` | `user` · `project` · `local` | 세션 간 학습 |
| `background` · `isolation` | `worktree` 만 유효 | 격리 |

**`hooks` · `mcpServers` · `permissionMode` 는 플러그인 에이전트에서 보안상 지원되지 않는다.** 그리고 플러그인 `settings.json` 은 `agent` 와 `subagentStatusLine` 두 키만 받는다 — 이것이 [ADR-0008](adr/0008-plugin-declarative-split.md)이 하네스를 둘로 쪼갠 이유다.

### 기존 방법

- **내장 서브에이전트** — `Explore` 등. 대부분 메인 대화의 모델을 상속한다.
- **`harness-100`** — 오케스트레이터 스킬 1 + 전문가 에이전트 4–5, **의존 DAG 와 병렬 표시**, `_workspace/NN_role.md` 로 핸드오프. 다만 **전부 산문 지시이고 frontmatter 에 `model` 도 `effort` 도 없다** — 강제되는 것이 없다.
- **Superpowers** — `subagent-driven-development` (503줄) · `dispatching-parallel-agents` (167줄).

### 우리 현황

**컨슈머용 sub-agent 를 하나도 배포하지 않는다.** 이 레버가 아예 없다. 저장소 자체용으로 `harness-reviewer` 하나가 있을 뿐이다.

**에이전트는 공짜가 아니다** — description 이 스킬과 같이 상시 로드된다. 티어를 내려 절약한 만큼 상시 비용이 붙는다.

### 측정

**안 쟀다.** 근거로 삼을 만한 관측은 하나 있다 — 한 세션에서 서브에이전트 12개를 띄웠고 경로 치환·개수 세기처럼 상위 모델이 필요 없던 것이 절반이었다. **그건 관측이지 측정이 아니다.**

재려면 같은 과제를 티어별로 돌려 **정확도 · 토큰 · 재작업률** 셋을 봐야 한다. 재작업률이 핵심이다 — 싼 모델이 놓친 것을 비싼 모델이 다시 하면 총비용은 오른다.

## 4. Graph engineering

### 정의

**코드베이스·문서를 구조로 만들어 질의하는 것.** "무엇이 무엇을 부르나", "이 변경이 어디에 닿나" 를 파일을 열어보지 않고 답하는 층.

### 설정 지점

| 어디 | 무엇을 |
|---|---|
| 그래프 산출물 디렉터리 (`graphify-out/` 류) | 지속되는 그래프 · 리포트 |
| 재빌드 트리거 (post-commit 훅) | 그래프가 코드와 어긋나지 않게 |
| 질의 인터페이스 (`query` / `path` / `explain`) | 사용 지점 |
| LSP 플러그인 | **다른 층** — 심볼 단위, 즉시, 상시 비용 0 |

### 기존 방법

**`graphify`** (ehr-research 프로젝트 스킬, 702줄) — 코드·문서·논문·이미지를 지속되는 지식 그래프로. god node, community detection, `query`/`path`/`explain`. 출처를 `EXTRACTED` / `INFERRED` / `AMBIGUOUS` 로 구분하는 감사 추적을 갖고, *"모르면 AMBIGUOUS 를 쓰고 절대 엣지를 지어내지 말라"* 를 규칙으로 둔다. post-commit 훅으로 재빌드를 건다.

**LSP** — 같은 질문의 다른 답. 심볼 정의·참조를 언어 서버에서 즉시 얻고 상시 비용이 0 이지만, *커뮤니티*·*이 문서가 저 코드와 어떻게 연결되나* 는 답하지 못한다.

**둘은 경쟁 관계가 아니다.** LSP 는 심볼 단위·즉시·정확, 그래프는 코퍼스 단위·비동기·근사. 그래프 쪽은 산출물이 크고(관측 당시 `graph.json` 5.2MB · `graph.html` 4.5MB · 리포트 120KB) 재빌드 비용이 든다.

### 우리 현황

**자산이 없다.** LSP 두 개를 프로파일 dependency 로 들이는 것이 전부이고, 그건 심볼 층이지 그래프 층이 아니다.

### 측정

**안 쟀다.** LSP 는 재봤지만 **결론이 없다** — 토큰 −6.3%, 이 설계로 검출 가능한 최소 효과가 61% 다. 그래프 층은 시도조차 안 했다.

재려면 먼저 답이 갈리는 질문 유형을 정해야 한다. "이 함수 정의 어디" 는 LSP 가 이기고, "이 결정이 어느 문서들에 흩어져 있나" 는 그래프가 이긴다 — **같은 자로 재면 둘 다 무의미한 수가 나온다.**

## 축을 가르는 이유

| 증상 | 어느 축의 문제인가 |
|---|---|
| 시크릿이 명령줄에 들어갔다 | harness — 가드 |
| 같은 실패를 세 번째 고치고 있다 | loop — 멈춤 조건 |
| 개수 세기에 최상위 모델을 썼다 | orchestration — 티어 |
| 이 변경이 어디에 닿는지 모르겠다 | graph — 이해 층 |

**섞으면 잘못된 자리를 고친다.** 루프가 안 멈추는 것을 가드로 막으려 하면 정상 작업을 막게 되고, 이해 부족을 오케스트레이션으로 풀려 하면 싼 모델을 더 띄우게 된다.

## 다음을 정하는 기준

새 자산을 이 넷 중 어디에 얹을지 정할 때:

1. **어느 축인가** — 축이 안 정해지면 무엇을 잴지도 안 정해진다.
2. **하드 레버가 있나** — `maxTurns`·`model`·`permissions` 는 강제되고, 규칙은 안 된다. 강제되는 것부터 본다.
3. **재는 방법이 서나** — R6 은 세 주장 중 하나만 잴 수 있었고, 그 하나가 0 이었다. **잴 수 없는 주장은 규칙으로 올리지 않는다.**
4. **상시 비용이 얼마인가** — `make context-budget`. 훅과 LSP 는 0, 스킬과 에이전트와 rule 은 아니다.
