# harness gaps — 원장

`CLAUDE.md` §5 의 "두 번 이상 발생하면 제안한다" 를 세기 위한 파일이다. 세션을
넘겨 발생을 세는 장치가 이것뿐이므로, **1회차도 적는다** — 1회차를 안 적으면
2회차가 영원히 1회차로 보인다.

한 항목: 날짜 · 파일:줄 · 무슨 일이 있었나 · 몇 회차인가. 2회차가 되면 그때
PR 본문 `## Notes` 로 올라가고, 고치는 것은 그다음이다.

## 2026-08-07 — `superpowers:finishing-a-development-branch` 가 위임을 받지 않는다

- **어디**: `docs/adr/0009-external-dependencies.md` — 갱신 절의 위임 판정
- **무슨 일**: ADR-0009 는 머지·브랜치 정리를 Superpowers 쪽에 남기고 우리는
  PR 생성까지만 한다고 정했다. 실측에서 "이 PR 머지하고 브랜치 정리해줘. squash
  로 넣고 원격 브랜치도 지워줘" 가 **세 번 다 `Bash` 로** 갔다. 위임한 상대가
  그 자리를 받지 않는다. 사용자는 규약 없는 맨 `git` 명령을 받게 된다.
- **왜 지금 안 고치나**: 1회차다. 그리고 고치는 방법이 둘인데 어느 쪽인지
  모른다 — 우리가 `pr-finish` 를 만들어 자리를 메우거나, 위임 자체를 철회하고
  `pr-create` 의 범위를 넓히거나. 둘 다 되돌리기 비싼 결정이라 두 번째 발생을
  기다린다.
- **2026-08-08 분류**: 대기 — 그리고 반대 증거가 하나 생겼다. 이번 세션에서
  "머지하고 retro" 에 이 스킬을 Skill 로 불렀고 정상 로드됐다. 원 관측은 *위임이
  Bash 로 샜다* 였는데, 명시적으로 부르면 동작한다. 2회차 조건을 "부르지 않았는데
  샜다" 로 좁힌다.
- **회차**: 1

## 2026-08-07 — R1-3 예외 조항이 "커밋 보류" 를 말하는데 커밋된다

## 2026-08-07 — 플러그인 `bin/` 은 사용자 셸에서 안 보인다

- **어디**: `install.sh` · `README.md` (설치 안내)
- **무슨 일**: 사용자가 터미널(zsh)에서 `harnessctl` 을 쳤는데 없었다. 플러그인
  `bin/` 은 Claude Code **Bash 도구** 의 PATH 에만 올라간다. README 는 그냥
  "PATH 에 자동으로 오른다" 고만 적어 두어 사용자가 터미널에서 칠 수 있는 것처럼
  읽혔다 — 설치가 깨진 것처럼 보인다.
- **왜 심링크로 못 푸나**: 캐시가 버전별 디렉터리(`harness-core/1.6.0/bin/`)라
  업데이트마다 경로가 바뀐다. 지금 거는 심링크는 다음 업데이트에 죽는다.
- **고친 방법**: `~/.local/bin/harnessctl` 에 실행 시점 해석 shim. 평범한
  실행 파일이라 셸 무관하고, `sort -V` 로 최신 버전을 고르므로 업데이트를 따라간다.
  PATH 에 없으면 `$SHELL` 을 보고 맞는 rc 파일과 한 줄을 안내한다.
- **1회차인데 왜 바로 고쳤나**: 사용자가 첫 명령에서 막혔다. 설치기가 "완료" 라고
  말한 뒤 안내한 명령이 동작하지 않는 것은 후보 기능이 아니라 결함이다.
- **회차**: 1 (해결됨)

- **1회차인데 왜 바로 고쳤나**: 기록되지 않은 설정은 이미 발표된 수치의 유효
  범위를 불명확하게 만든다. 문서가 거짓을 말하는 상태에 가깝다.
